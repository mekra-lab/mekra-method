# Profiles

A profile is a starting point that combines multiple patterns for a particular usage mode. Directory names and example structures may be changed to fit the situation, and matching a profile does not determine OKF conformance.

| Profile | Best suited for |
| --- | --- |
| [Project repository](project-repo/README.md) | Code is central and OKF supports project knowledge |
| [Knowledge-only](knowledge-only/README.md) | Knowledge itself is the primary output |
| [Large corpus](large-corpus/README.md) | Hundreds or thousands of PDFs, documents, or other materials |

Add profiles for professional knowledge, hybrid repositories, and other cases only when real examples accumulate and the existing profiles no longer explain them well. Do not pre-fill the repository with profiles for hypothetical future cases.

The reasoning behind design choices lives in the [OKF knowledge graph](../okf/index.md). Profiles apply that knowledge to particular usage modes.

A profile describes the operating model; it does not determine the operation, such as initial construction or updating existing practices, or this application's scope. See [adoption judgment](../okf/adoption.md) for that distinction and the [application guide](../APPLICATION.md) for a starting path. After applying the chosen configuration, leave the source-material and new-knowledge intake locations and incorporation method in the target repository.
